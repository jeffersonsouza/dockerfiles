# PHP 8.6.0 vs PHP 8.5.13 load comparison — 2026-11-22

All **12 profile executions / 60 stages** passed, completing **1,312,939 requests** with **zero HTTP/client errors, zero OOM events and zero service restarts**. All final healthchecks were healthy, every container stopped with exit code 0, and all temporary test containers were removed.

The index throughput medians were close: PHP 8.6 was **1.73% lower at 256 MiB** and **1.54% higher at 512 MiB**. The three-run ranges overlap in both profiles. These measurements support treating the two images as broadly similar for this synthetic workload; they do not establish a PHP-version performance ranking.

## Environment and method

- Executed from 22:18:20 to 22:29:42 on 22/11/2026, Europe/Berlin (UTC+01:00).
- Native ARM64, Docker Desktop / Engine 29.9.2, cgroup v2. The Docker VM has 10 vCPUs and approximately 10.19 GiB RAM.
- Other project containers were active and consuming CPU. The load generator ran on the same Mac. Only one benchmark container ran at a time; the host was shared throughout.
- Every benchmark container had a 1-vCPU CPU quota, no swap, 64 MiB OPcache, disabled JIT, and a 128 MiB PHP memory limit per request.
- Profiles: 256 MiB with one FPM worker; 512 MiB with two FPM workers. RAM and worker count change together, so their individual effects are not isolated.
- Each profile was repeated three times in a fresh container. Round 1: 8.5 then 8.6 at 256 MiB, followed by 8.5 then 8.6 at 512 MiB. Round 2 reversed both profile and version order. Round 3 repeated round 1.
- The existing `.github/scripts/load-test-php.py` was copied unchanged before execution. Each run warmed the index with 20 requests and exercised five 10-second stages: uncached JSON index at 1, 8 and 32 clients; a no-store route allocating 96 MiB, computing 10,000 PBKDF2 iterations and sleeping 20 ms at 32 clients; and a primed public FastCGI cache response at 32 clients.
- Cache HIT and no-store behavior, changing response timestamps, health, errors, cgroup OOM counters and graceful shutdown were checked by the existing runner.
- ApacheBench 2.3 (revision 1923142), HTTP/1.0. `-k` was requested, but all runs recorded zero effective keep-alive requests.
- Throughput and latency below are medians of three independent runs. The reported p95/p99 values are medians of each run's percentile, not percentiles pooled across all requests. Ranges show observed minima and maxima, not confidence intervals.

## Change from PHP 8.5.13 to PHP 8.6.0

Positive throughput changes mean more requests per second. These small differences should be read together with the overlapping run ranges below.

| RAM (MiB) | Index c32 throughput | Heavy throughput | Cache throughput | Median container peak change (MiB) |
| --- | ---: | ---: | ---: | ---: |
| 256 | -1.73% | +2.70% | -0.53% | +11.0 |
| 512 | +1.54% | +0.90% | +1.10% | -5.9 |

The 512 MiB/two-worker profile increased median heavy-route throughput by 35.8% for PHP 8.5.13 and 33.4% for PHP 8.6 compared with their 256 MiB/one-worker profiles. Both remained limited to 1 vCPU.

PHP 8.6 used more container memory in the 256 MiB runs and slightly less in the 512 MiB runs. All observed peaks remained below the configured limits. The public cache scenario mostly exercises NGINX and the host; a warmed HIT does not execute PHP on every request.

## Reproduction and raw evidence

The runner matches repository commit `d9e1142`. Its SHA-256 is `d429ad348c511c454a3997ae331f44648bce3178455e11b04ad61a95caf8702d`.

```sh
python3 .github/scripts/load-test-php.py \
  jeffersonsouza/php@sha256:e7ea9a4bedba63f4f08d5f609fb3490b551315977d2d72855c9890d16e69a73b \
  8.5 --memory 256 --children 1 --output /tmp/php8513-load-256-r1
python3 .github/scripts/load-test-php.py \
  jeffersonsouza/php@sha256:cd6df4cbb34d93159af907d0ef12820a8b8d1914bc1aef69f1b6e3b1cd9e0f93 \
  8.6 --memory 512 --children 2 --output /tmp/php860-load-512-r1
```

Run both images with each memory/worker pair in fresh output directories, following the three-round order above. The default stage duration is 10 seconds.

Raw output is retained locally outside Git at `/private/tmp/php-load-2026-11-22.eaVnTJ/`: `comparison.json` contains all 12 summaries and aggregates; `metadata.json` records image identities and environment; each `round-*/` directory contains five ApacheBench outputs, a container log and `summary.json`. The unchanged runner snapshot, execution-order wrapper and full progress log are included there.

## Scope

These are short synthetic ARM64 measurements on a shared host, with three repetitions per profile and different Alpine bases. They exclude the real application, databases, Redis workloads and TLS. No AMD64 load run or sustained HTTP/1.1 benchmark was performed. They describe the observed workloads and do not establish production capacity or statistical significance. The October reports remain historical measurements made under earlier host conditions.
